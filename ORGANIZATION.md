# Directory organization — nfl-prediction-project

This file is the source of truth for how this project directory is laid out. Anything added to this directory should follow this structure; if something doesn't fit, extend this document with a new section rather than dropping a file wherever.

```
nfl-prediction-project/
├── ORGANIZATION.md          ← this file
├── data/
│   ├── raw/                 ← untouched downloads from nflverse. Never edited by hand or by a
│   │                          script. Only overwritten by re-running 01_download_raw_data.sh.
│   │   ├── games.parquet, players.parquet, player_stats_offense/defense.parquet
│   │   ├── injuries_all.parquet + injuries/        (per season, 2009+)
│   │   ├── player_stats_weekly/                    (2025+ player stats, new nflverse format)
│   │   ├── download_log.json                       (when each file was downloaded; used to
│   │   │                                            time-stamp 2025+ injury reports)
│   │   ├── season_rosters/                         (per season)
│   │   └── weekly_rosters/                         (per season, 2002+)
│   └── processed/           ← derived tables, rebuilt from data/raw/ by scripts/, never hand-edited,
│       │                      trimmed to 1999-2024.
│       ├── source tables (02):   nfl_games_*, nfl_player_*_stats_weekly_*, nfl_players_master,
│       │                         nfl_season_rosters_*, nfl_weekly_rosters_*   ← contain outcomes /
│       │                         non-point-in-time data; inputs only, never train on these directly
│       └── modeling tables (03): nfl_model_features_*   ← pre-game features only
│                                 nfl_model_labels_*     ← outcomes (join on game_id)
│                                 nfl_market_benchmark_* ← Vegas lines, benchmark only
│                                 nfl_team_features_pregame_* ← same features, one row per team-game
├── docs/
│   ├── data_dictionary.md              ← every modeling column, what's excluded and why, modeling rules
│   ├── leakage_verification_report.md  ← generated by 04 on every run
│   └── data_audit_2026-09-22.md        ← initial audit of the old pipeline (issues now fixed)
├── modeling/                ← model training + evaluation (reads only data/processed/ modeling tables)
│   ├── README.md                   ← protocol, results, how to run
│   ├── predict.py                  ← THE TOOL: predict any week with the saved best model
│   ├── common.py, 01_validate.py, 02_final_test.py, 03_fit_production.py
│   ├── 04_market_residual_experiment.py, 05_attention_experiment.py  (experiments, not adopted)
│   └── results/                    ← selection.json, validation summary + validation_oof/,
│                                     test results/predictions, production_models.joblib,
│                                     market_residual/, attention/
├── predictions/             ← output of predict.py: <season>_week<NN>.csv, one file per week
└── scripts/                 ← the build pipeline, run in numeric order from the project root
    ├── 01_download_raw_data.sh
    ├── 02_build_core_tables.py
    ├── 03_build_pregame_features.py   ← point-in-time feature builder (the leakage rule lives here)
    └── 04_verify_no_leakage.py        ← must exit 0; rebuilds features with all future info scrambled
```

## Rules for adding to this directory

- **Raw vs. processed is a hard line.** If a file came from an external source unmodified, it goes in `data/raw/` and is treated as read-only. If it was computed, joined, filtered, or aggregated by us, it goes in `data/processed/`. Nothing straddles both.
- **Any change to `03_build_pregame_features.py` must be followed by `04_verify_no_leakage.py`, and it must pass.** Features, labels and the market benchmark stay in separate files. Never add an outcome or a Vegas line to the feature file.
- **Every script in `scripts/` is numbered and idempotent.** Re-running the whole sequence from a clean `data/raw/` should reproduce `data/processed/` exactly. A new pipeline step gets the next number (`05_...`); don't insert in between existing steps.
- **`data/processed/` files are named `nfl_<contents>_<season range>.<ext>`.** Keep that convention for anything new (e.g. a future `nfl_ngs_features_2016_2024.parquet` for Next Gen Stats, if that gets added — see the "not yet built" list in the data dictionary).
- **Both CSV and Parquet are provided only for the small/frequently-opened files** (games, players, matchup features, team game log). The large per-player-per-week tables and weekly rosters are Parquet-only to keep the directory size reasonable — don't add a CSV version of a large table without a specific reason.
- **Experiment-specific scripts (e.g. the anonymization/randomization step for the LLM test) belong in a new `experiments/` folder**, not in `scripts/` — `scripts/` is strictly the data-build pipeline. Create `experiments/` when the first such script is added, with its own short README if it grows past one file.
- **`modeling/predict.py --refresh` is the one exception to "raw is written only by 01".** It re-downloads the schedule and the current seasons' stats/injuries into `data/raw/` and logs the download time.
- **No stray files at the project root.** Anything that isn't `ORGANIZATION.md` belongs in one of the subfolders above.
- **`modeling/` never touches the test seasons (2023–2024) during model selection.** `01_validate.py` filters them out at load. Any new model is compared on validation first; the test set is scored only after the choice is written to `results/selection.json`. A new model version gets its own `results/` entries rather than overwriting the frozen v1 test results.
- **Update this file whenever the structure changes** — new top-level folder, new naming convention, new stage in the pipeline. This document should always describe the directory as it actually is, not as it was when first written.

## Current status

As of 2026-09-23 the best model (v1 ensemble) is saved and usable weekly via `modeling/predict.py`, retrained on every completed game through 2026 week 2. Out-of-sample on the full 2025 season it scored 63.4% (Vegas 65.8%), consistent with the 2023–24 test (64.7%). See `modeling/README.md`.
